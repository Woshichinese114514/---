# 游戏规则与运行规范（Rules & Spec）

> 本文件是 `sim` / `ai` / `scoring` / `cli` 四个 crate 共同的规则真源。
> 数值改动必须同步：`sim::RulesConfig` 默认值、本文件、`docs/replay-format.md`（若影响回放）、
> 必要时升 `RULES_VERSION`。**规则判定、边界情况、冲突结算、种子解析、评分公式都要有解释性注释**
> （解释设计意图与「为什么这么做」，而不是复述代码）。

## 1. 地图与地形

- 方格地图，默认 **25×25**（可配置 `--map-width/--map-height`；最小可用尺寸以能放下阵营区与中心区为准）。
- 坐标：`x` 向右、`y` 向下，原点左上；`idx = y * width + x`（行优先）。
- 地形四种：
  - `Empty`：可通行、可放炸弹、旗可以刷/掉在此。
  - `Wall`：阻挡移动、**阻挡视线**、**阻挡炸弹十字爆炸的继续传播**（墙后的格子不受影响）。
  - `Void`：**可进入，但进入即死**（`rules_version >= 2`；虚空是「深渊」而不是「墙」：
    移动判定允许走上去，结算时该单位当场死亡，见 §9 第 3 步）。不可放置任何东西、
    旗不会掉在此、部队不会在此复活；**不阻挡视线**；**不阻挡炸弹爆炸**（爆炸只在墙上停，
    所以虚空格上的单位照样被炸到，而下落本身已经先把它带走了）。
    —— 与 `Wall` 的区别必须记牢：墙是「走不进去、挡视线、挡爆炸」，虚空是「走得进去、
    挡不住任何东西、走进去就死」。协议层用 `Terrain::can_be_entered()`（含虚空）与
    `Terrain::is_lethal()`（仅虚空）把两者分开，而 `is_walkable()` 只表示「能安全站在上面」。
  - `TeamBase(team_id)`：阵营格。
- **阵营区（3×3）**：每队一个，是出生点、复活点、得分区。规则：
  - 敌方单位不能进入己方阵营（自己的单位可以进自己阵营，队友之间仍互相阻挡）。
  - 阵营内**禁止放炸弹**。
  - 阵营内的单位**免疫爆炸伤害**（防止刚复活就被自己的炸弹炸死）。
  - 阵营内不会刷旗；旗掉落也不会落在任何阵营格。
- 阵营区左上角坐标由 `mapgen` 决定（见 `docs/internal-api.md` 第 2 节），
  同时也是回放 `init.teams[].base_x/base_y` 的值。`init.teams[].base_*` 与地形数组里的
  `TeamBase` 编码必须一致（由 `mapgen` 保证）。
- 地图生成（`mapgen`）：
  - 带种子 RNG，**同种子 + 同版本必须产出完全相同的地图**（逐格比较，必须写测试）。
  - 生成后**必须 BFS/DFS 校验连通性**：每个阵营区到中心区域至少一条通路。
    不通则用**同一个 RNG 继续抽**（继续在本 RNG 上迭代，不要换种子、不要重新开 RNG——
    换种子会破坏「种子 → 地图」的确定性契约）。
  - 中心区域不能全是墙；阵营区 3×3 不能与墙/虚空重叠。
  - 生成算法定型后**不要原地修改**：要改就加 `generate_v2` 并升 `MAP_GEN_VERSION`。

## 2. 单位与行动点

- 每队 **3 个单位**（`units_per_team = 3`）。
- 每个单位 HP **3**、上限 3、**无回血**，命中一次扣 1。
- 死亡：HP 归 0 → 进入复活倒计时 **10** tick；每个 tick 减 1；到 0 时在己方 3×3 阵营内找空格复活，
  复活后满血 3。**若阵营满员，则留在倒计时 0 的状态，下个 tick 继续尝试**（不要卡死、不要刷到阵营外）。
- 死亡来源有两种，都必须走同一条「进入复活倒计时」的路：
  - HP 归 0（被攻击/被炸弹）→ 击杀数记给致死者（炸弹记给放炸弹的队伍，包括自炸/友伤）；
  - **站到虚空格上**（`rules_version >= 2`，见 §1 与 §9 第 3 步）→ 环境致死，`by = null`，
    **不计任何队伍的击杀**（避免「把队友推下去」变成刷击杀的捷径）。
- 死亡单位**不在地图上**（不阻挡移动、不可被攻击、不阻挡视线）。
- 存活单位**阻挡移动**（其他单位不能进入其所在格）。
- 每单位每回合 **2 AP**。行动消耗：
  | 行动 | AP | 限制 |
  |---|---|---|
  | 移动 1 格（上下左右） | 1 | 目标格可进入 |
  | 攻击 | 1 | 每单位每回合**最多 1 次** |
  | 放炸弹 | 1 | 放在自己当前格；阵营内禁止 |
  | 拾旗 | 1 | 必须站在旗的格子上 |
  | 等待 | 0 | 默认兜底 |
- 攻击后仍可继续移动/放炸弹/拾旗（只要还有 AP）。

## 3. 攻击

攻击成立需**全部满足**：

1. 攻击者存活，且本回合未攻击过；
2. 目标是敌人（`team != attacker.team`）；
3. 目标存活；
4. 曼哈顿距离 ≤ **3**；
5. 两点之间**有视线**（中间格不含墙）。

- 伤害固定 **1**；命中后标记「本回合已攻击」。
- 视线判定：在两点之间做 Bresenham/超覆盖直线，检查**除起点与终点外**的所有格；
  任一格 `blocks_sight()`（即墙）则无视线。**单位不阻挡视线**（当前规则，注释里写明这个选择）。
- 同一 tick 内两个单位攻击同一目标：**按行动顺序依次结算**（先手可能先击杀目标，后续攻击打到尸体则失败 → 记非法动作事件）。

## 4. 炸弹

- 放置消耗 1 AP，放在放置者当前格；炸弹**不阻挡移动**、不阻挡视线。
- 倒计时 `bomb_fuse = 2`：放置当回合计时为 **2**；之后每经过一个 tick 减 1；
  减到 **0 的那个 tick 结算阶段爆炸**。因此回放里只能看到 `timer = 2`、`1`。
- 爆炸范围：**十字**（上下左右四个方向），半径 `2`；传播遇 **墙立刻停止**（该方向后续格子不受影响）。
- 伤害 `2`，**有友伤**（可以炸伤/炸死自己与队友；击杀统计见第 6 节）。
- **阵营格免疫爆炸**：站在任意阵营格里的单位不受爆炸伤害（也不因此死亡）。
- 炸弹可以**堆叠在同一格**，各自独立倒计时；`BombView` 每枚一条。
- 炸弹不能被攻击摧毁；旗子也不能被炸弹摧毁。

## 5. 旗

- **中心区域**：到地图中心曼哈顿距离 ≤ `flag_capture_radius = 4` 的格子。
- 每 `flag_spawn_interval = 5` 个 tick 检查一次：若场上旗数 < 最大旗数（= 队伍数；
  2 队最多 2 面、3 队最多 3 面），则**随机刷新 1 面**旗。
  - 检查点定义：在第 `t` 个 tick 结算末尾，当 `t % 5 == 0` 时检查（`t ≥ 5`）。
  - 候选格必须：在中心区域内、非墙非虚空、不在任何阵营区内、没有其他旗/单位/炸弹。
  - 若没有合法候选格，本 tick 不刷（下个检查点再试）。
- **拾旗**：单位站在旗格上，花 1 AP 拾取，旗跟随单位。已携带旗的单位不能再拾另一面旗（规则：
  一个单位最多携带 1 面旗；拾第二面按非法动作处理）。
- **携带旗的单位**：可以移动、放炸弹；**默认不能攻击**（`flag_carrier_can_attack = false`，
  拿旗者只能跑，增加抢旗风险）。开关为 `RulesConfig.flag_carrier_can_attack`。
- **得分**：携带者进入己方 3×3 阵营内 → **自动得分**，队伍 +1，旗消失（下一检查点可能刷新新旗）。
  得分事件带 `new_score`。得分不消耗 AP（是状态触发，不是主动动作）。
- 旗不能被摧毁；掉落的旗可以被任意队伍拾取（包括原持有队）。

## 6. 死亡与掉旗

- 携带旗的单位死亡时，旗掉落在**死亡位置周围 3×3** 内的随机合法格。
  **随机池不含死亡格本身**：死亡格必然属于它自己的 3×3，若把死亡格算进第一级，
  后面几级就永远不会被触发、规范里单列的阶梯会退化成死代码；而且「周围」的字面含义是邻域而非自身。
  - 候选格必须：非墙非虚空、不属于任何队伍阵营区、没有其他旗/单位/炸弹。
  - 四级阶梯（逐级尝试，任一级成功即停止，成功时生成 `flag_dropped` 事件）：
    1. **3×3**：死亡格周围切比雪夫距离 ≤ 1（不含死亡格）；
    2. **5×5**：切比雪夫距离 ≤ 2（不含死亡格）；
    3. **中心区域**：曼哈顿距离中心 ≤ `center_radius` 的合法格里随机一格；
    4. **死亡格本身**（若该格合法且非阵营格）；
    5. 全部失败（极端情况）→ 该旗**暂时退场**：不进入 frame 的 `flags` 列表、不发事件，
       直到下个刷旗检查点重新出现。
  - 第 4/5 级是规范原文（只写到「中心区域」）之外的兜底扩展，引擎的取向是**尽量把旗留在场上**，
    只有连中心区域都挑不出合法格时才让旗退场；四级都由
    `flag_drop_falls_back_to_wider_ring_then_center` 回归测试锁住，改语义必须同时改测试。
- 死亡单位按第 2 节规则复活，与旗无关。

## 7. 同时进一格冲突结算（关键判定）

**必须**在 tick 结算时先把所有队伍的动作收集齐，再统一判定移动，不能边收边执行。

算法（`sim` 实现时必须完全按此顺序，并在注释里解释每一步的意图）：

1. **收集移动意图**：所有存活单位中，本回合提交了 `Move(dir)` 且 AP ≥ 1 的意图。每单位至多 1 个。
2. **统计目标格**：`target -> 请求者列表`。
3. **冲突判定**：若某目标格被 **≥ 2** 个单位同时请求 →
   所有请求者**都消耗本次移动的 1 AP**，但**都留在原地**；生成 `move_conflict` 事件（含该格坐标与全部请求者）。
4. **单请求者判定**：
   - 目标格地形不可进入（越界/墙/敌方阵营）→ 移动失败。**失败不消耗 AP**（本项目明确选择：
     地形不可进入是「AI 的规划错误」，惩罚交给出错的一方已经足够；消耗 AP 会让随机 AI 被自己的错误
     双重惩罚，也会让回放里的 AP 消耗难以解释。**这条决定必须写在代码注释里**）。
     > 注意与第 3 步的区别：**冲突（撞人）消耗 AP，撞墙不消耗 AP**。
     > 虚空**不在**此列的拒绝条件里（`rules_version >= 2`）：走进虚空是一次**成功**的移动，
     消耗 1 AP，然后在 §9 第 3 步当场死亡——把它当「不可进入」会让 AI 完全看不见这条风险，
     也让「深渊」失去意义。
   - 目标格被其他单位占用：若占用者本回合**也会成功离开**该格，则允许进入（换位/接力）；否则失败（不消耗 AP）。
     「成功离开」的判断见第 5 步。
5. **离开判定（处理链式与环状交换）**：用**不动点迭代**判断每个意图是否成功：
   - 先假设所有通过第 3、4 步地形检查的意图都「会成功」；
   - 重复扫描：若某意图的目标格被一个「不会成功离开」的单位占用，则把该意图标记为失败；
   - 直到不再有变化。
   - 这样 `A→B, B→A`（双人交换）双方都成功；`A→B, B→C, C 站着不走` 时 A、B 都失败；
     环（A→B, B→C, C→A）全部成功。
6. **执行移动**：成功的单位更新坐标并生成 `unit_moved` 事件；失败的（除冲突者外）不消耗 AP。
7. 任何被拒绝的动作都要生成 `illegal_action` 事件（`action` 用 `Action::label()` 的文本，
   `reason` 是人类可读原因，如 `"AP 不足"`、`"目标是墙"`、`"目标格被占用"`、`"敌方阵营"`、`"本回合已攻击"`）。
   **冲突（撞人）不算非法动作**，它有专门的 `move_conflict` 事件。
8. 同一 AP 池的结算顺序必须是：移动 → 攻击 → 放炸弹 → 拾旗（每个动作结算后重查 AP 是否够用）。

## 8. 胜负判定

- 每局 `max_ticks`（默认 **300**）全局回合后结束。
- 默认 `WinCondition::HighestScore`：**最高分唯一** → 该队胜；**多队并列最高** → 平局
  （`winner = null`）；否则为负。
- 留钩子：`WinCondition::HighestScoreThenKills`（并列时比击杀，再并列仍为平局）；
  `all_dead_loses`（可选：全灭判负，默认关闭）。
- 平局/胜负的最终分类由 `scoring::OutcomeRule` 再做一次（默认 `HighestScoreRule`，与上一条一致），
  便于将来替换成 ELO/TrueSkill 风格规则。

## 9. 单个 tick 的结算顺序（`Sim::step` 必须严格按此实现）

1. 回合开始：清空所有单位的「本回合已攻击」标记，AP 重置为 2（存活单位）；
   死亡单位 AP 为 0；刚复活的单位本回合不能行动（见第 2 节的自然结果）。
2. 按**轮换顺序**让每队 AI 决策并收集动作：
   顺序为 `(tick + slot) % teams`（tick 从 1 起），即多队时行动顺序每回合轮换，避免固定先手优势。
   给 AI 的 `Observation` 必须是**本 tick 决策前**的状态快照。
3. 统一结算移动（第 7 节）→ **虚空致死** → 攻击 → 放炸弹 → 拾旗。
   - 「虚空致死」紧跟移动：只要某存活单位**所在格**是 `Void`，就当场死亡（生成 `unit_died`，
     `by = null`，即环境致死，不计入任何队伍的击杀数）。
     判定依据是**地形**本身而不是「谁提交了移动」——被挤、被换位推上虚空的单位一样死；
     按单位 ID 稳定顺序结算，保证同种子同回放。
     必须放在攻击之前：死人不该在同一 tick 继续开火（否则「跳坑」会变成「一次免费的突进」）。
4. 炸弹倒计时减 1，减到 0 的立刻结算爆炸（十字、被墙阻挡、阵营免疫、友伤）。
5. 复活倒计时减 1，到 0 的尝试在己方阵营复活（阵营满员则延后）。
6. 旗刷新检查（第 5 节）。
7. 得分检查（携带者在己方阵营 → +1，旗消失）。
8. 胜负/结束检查（达到 `max_ticks` 则 `is_over`）。
9. 构造并返回 `RenderFrame`。

**随机性纪律**：整局只用构造时用 `seed` 初始化的**同一个** `sim::Rng`；
炸弹爆炸、旗刷新、掉旗位置、随机候选格都从它取数。不要用系统时间、不要用线程本地随机、
不要在 sim 里创建第二个 RNG。AI 的随机用**自己**的 `ai_seed` 播种的 RNG。

## 10. 种子模式（`cli`）

三种模式：

| 模式 | 语义 | `--seed` | `--base-seed` |
|---|---|---|---|
| `per-match`（默认） | 每局一个新随机种子（每局地图不同） | 忽略 | 可选：给定后整批种子序列可复现 |
| `fixed-random` | 随机**一个**种子，批量全部复用（所有局同图） | 忽略 | 可选：让「随机」本身可复现 |
| `fixed` | 用户指定固定种子 | **必填** | 忽略（用不上；固定种子本身就是确定的） |

要点：

- `--base-seed` **只播「种子生成器」，不直接播地图**。这样即使每局随机，只要给了 `--base-seed`，
  整批种子序列可复现（同 base-seed + 同 seed-mode + 同局数 → 逐局种子完全一致）。
- `per-match` 的种子数组必须在**并行前一次性生成**（保证并行时顺序稳定、可复现）。
- `per-match` 的 AI 种子：`ai_seed = match_seed ^ ((team_id as u64) << 32) ^ 0x9E37_79B9`。
- **`fixed-random` 的已知陷阱**：所有局地图相同，如果 AI 也完全确定，则所有局结果一模一样，
  统计毫无意义。因此 `fixed-random` 与 `fixed` 模式下，**地图种子固定，但每局的 AI 随机盐按局索引
  确定性推导**：`ai_salt[i] = splitmix64(map_seed ^ (i as u64) ^ 0x51ED_2701)`，
  再 `ai_seed = ai_salt[i] ^ ((team << 32)) ^ 0x9E37_79B9`。
  这样「地图固定、AI 随机可复现」——同 base-seed/同固定种子重跑仍然逐局一致。
- **`splitmix64(x)` 的口径必须说清（易踩坑）**：本节写的是**标准一次性哈希**
  「先 `x += 0x9E37_79B9_7F4A_7C15` 再混淆」，即 `cli::seed::mix64(x)`
  （等价 `mapgen::Rng::new(x).next_u64()`）。
  它与 `mapgen::splitmix64(x)`（`Rng::next_u64` 内部那步**纯输出混淆**，不先加黄金常量）
  **不是同一个函数**：`mapgen::splitmix64(0) == 0`，而 `mix64(0) == 16294208416658607535`。
  两处口径差一次加法，照名字混用会让整批种子全变——`crates/cli/src/seed.rs` 里
  `mapgen_splitmix64_is_not_the_one_shot_hash` 测试专门钉死这条差别。
- 每局的完整种子（地图种子 + ai_seeds）必须写进 `matches.jsonl` 与该局 `ReplayInit`，
  以便单局复现。

## 11. CLI 规范

```text
qfr run [OPTIONS]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--matches N` | 1 | 批量对局数 |
| `--max-ticks N` | 300 | 每局最大全局回合数 |
| `--teams N` | 2 | 队伍数，只允许 2 或 3 |
| `--ai N=name` | 未指定者 = `random` | 第 N 队用哪个 AI，可重复；名字必须在注册表里 |
| `-o`, `--out DIR` | `out` | 输出目录（不存在则创建） |
| `--replay-sample all\|none\|N` | `all` | 回放保存策略：全部 / 不存 / 前 N 局 |
| `--map-gen-version N` | 1 | 地图生成版本（不支持时明确报错） |
| `--seed-mode per-match\|fixed-random\|fixed` | `per-match` | 见第 10 节 |
| `--seed N` | — | `fixed` 模式必填，其他模式忽略并给出提示 |
| `--base-seed N` | — | 让随机种子序列可复现 |
| `--jobs N` | 0 | 并行线程数，0 = 自动 |
| `--map-width/--map-height N` | 25 | 地图尺寸 |
| 评分权重 | 见 `ScoringConfig` | `--weight-win-rate/--weight-score-share/--weight-kill-ratio/--baseline-rating/--points-per-decade` |
| `--units-per-team N` | 3 | 预留；默认 3，非 3 时警告规则未针对该值调参 |

用法示例（README 里要有这三条）：

```bash
# 每局随机地图，跑 1000 局，3 队分别用不同 AI
./scripts/cargo run -p cli --release -- run --matches 1000 --teams 3 \
    --ai 0=greedy_flag --ai 1=defender --ai 2=random --out out/3p_1000 --jobs 0

# 固定随机：随机一张图，跑 500 局，随机序列可复现
./scripts/cargo run -p cli --release -- run --matches 500 --seed-mode fixed-random \
    --base-seed 20240501 --out out/fixedrandom_500

# 固定种子：指定种子跑 100 局
./scripts/cargo run -p cli --release -- run --matches 100 --seed-mode fixed \
    --seed 12345 --out out/fixed_100
```

## 12. 输出目录（四件套）

```text
<out>/
  manifest.json    配置、版本号三件套、种子信息、创建时间
  summary.json     评分汇总（按 AI 名字聚合 + 按槽位聚合）
  matches.jsonl    每局一行（protocol::MatchResult，无 type 字段）
  replays/match_00000.jsonl ...  回放（init/frame/end）
```

- `manifest.json`：引擎/规则/地图生成版本、创建时间、种子模式、`base_seed`、`fixed_seed`、
  解析后的种子信息（模式、base_seed、前几个种子样本、总数）、完整配置（局数、max_ticks、队伍数、
  每队 AI、地图尺寸、评分权重、`--jobs`、`--replay-sample`）。
- `summary.json`：`ScoringReport`（含 `teams` 与权重，明确标注分数所属体系）。
- 写入要求：**先并行跑完、把结果与回放在内存收集，再单线程统一写盘**；
  `matches.jsonl` 按局索引升序、回放按局索引编号，方便查单局。

## 13. 基线 AI 规格

| 名字 | 要求 |
|---|---|
| `random` | 纯随机基线：随机移动、随机攻击射程内敌人、随机放炸弹、随机拾旗；必须遵纪守法（只提交合法动作）。用 `ai_seed` 播种自己的 RNG。 |
| `greedy_flag` | 优先抢旗：前往最近的（地上）旗；拾起后**沿最短路径回己方阵营**得分；路上若敌人进入射程且拿旗不能攻击则忽略攻击（默认规则下拿旗者不攻击）。 |
| `defender` | 守家：待在己方阵营附近（不主动抢旗），攻击进入攻击范围（≤3 且有视线）的敌人，必要时回到阵营。 |

三者都要：`TeamAi` 实现、`name()` 返回注册名、每局新建实例、**不得 panic**、不访问 sim 内部状态
（只能通过 `Observation`）。建议实现一个共享的「选择朝向目标的最优一步」辅助函数并写注释。

第四个内置 AI `raider` **不属于基线规格**：它是"流水线抢旗"的得分参照实现
（互斥分旗、携带者避险、拦截敌方携带者、窄走廊 2-环换位），设计与实测见
`crates/ai/src/raider.rs`。它同样必须遵守本节的三条纪律（可复现、不 panic、只看 `Observation`）。

## 14. 测试清单（必须覆盖）

`mapgen`：

1. 同种子两次生成 `generate`，地形数组逐格相同；不同种子（大概率）不同。
2. 连通性：每个阵营区到中心区域有通路（BFS）。
3. 阵营区 3×3 全部是 `TeamBase(team)`，且不与墙/虚空重叠；中心区域不全是墙。
4. 2 队与 3 队都能生成；非法队伍数/过小地图返回 `Err` 而不是 panic。

`sim`：

5. 攻击判定：距离 3 可打、距离 4 不可打、中间有墙不可打。
6. 每回合攻击一次：同单位同回合攻击两次，第二次失败并产生 `illegal_action`。
7. 同时进一格冲突：两单位同 tick 进同一格 → 都留在原地，AP 都消耗，产生 `move_conflict`。
8. 交换位置：A→B 格、B→A 格，双方成功。
9. 撞墙不消耗 AP（撞人消耗 AP）——这条容易被误实现，必须有测试。
10. 死亡掉旗：携带者死亡，旗落在 3×3 内合法格（非墙非虚空非阵营、**且不是死亡格本身**）；
    3×3/5×5/中心/死亡格/退场 五级兜底各有断言。
11. 复活：死亡后 10 tick 复活、满血、在己方阵营内；阵营满员时延后。
12. 得分：携带旗进入己方阵营 → 队伍 +1、旗消失、产生 `score` 事件。
13. 炸弹：放置后 2 tick 爆炸、十字半径 2、被墙阻挡、阵营内免疫、友伤生效、计时值只出现 2/1。
14. 整局可复现：同配置跑两次，`ReplayBundle::to_jsonl()` 输出逐字节相同。
15. 虚空致死（`rules_version >= 2`）三条：
    ① 走进虚空是**合法移动**（消耗 1 AP、无 `illegal_action`），同 tick 死亡、
    `unit_died.by = null`、任何队伍击杀数都不变、复活倒计时 = `respawn_ticks`；
    ② 该 tick 的后续阶段（攻击/炸弹/拾旗）不再执行——死人不能继续开火；
    ③ 掉旗/刷旗/复活选点用 `is_walkable()`（排除虚空），例如死亡格周围 3×3 全是虚空时
    掉旗必须扩到 5×5 且落点不在虚空上。
16. 复活点在阵营内：手工把单位打死并推进 `respawn_ticks`，断言复活坐标落在
    `init.teams[team].base_*` 的 3×3 内（用户可见的「单位站在阵营正上方一格」问题必须被断言挡住）。

`ai`：

17. 注册表：`register_all()` 含四个名字（三个基线 + `raider`）；`create` 未知名字返回 `None`；重名覆盖。
18. 每个基线 AI 随机跑一整局（用 `sim::play`）不 panic、不产生「非法动作」事件（除设计允许的少数）、
    且同 `ai_seed` 两次运行结果一致。
19. 反死循环：多种子跑整局，统计 A→B→A「横跳」次数，要求**多数种子**落在典型上限内、
    且任何种子不超过硬上限（判据与校准数字见 `crates/ai/src/greedy_flag.rs` 的常量文档）。

`scoring`：

20. 评分公式稳定：固定输入 → 固定输出（写死期望值）。
21. 语义测试：`strength` 从 0.5 变到使 odds 提高 10 倍时，rating 恰好 +500（容差 1e-6）。
22. 聚合正确性：手造 3 局结果，校对胜/平/负、平均分、评分。

`cli`：

23. 三种种子模式行为符合第 10 节（含 `per-match` + `--base-seed` 两次运行种子序列一致）。
24. 批量可复现：同 `base-seed` + 同 `seed-mode` + 同局数跑两次，`matches.jsonl` 逐行相同。
25. 集成：跑 100 局 random vs random 无 panic；回放文件能被 `tools/validate_replay.py` 通过。
26. 表格对齐：中英混排的表，每一行的**显示宽度**必须相等（东亚宽字符按 2 列；
    见 `crates/cli/src/textwidth.rs` 的单测）。

Web UI 的测试见 `webui/README.md`。
