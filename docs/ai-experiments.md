# AI 对抗实验记录（`raider` 之后）

> 目标：以 `raider` 为基线，做一个更强的抢旗 AI。
> 结论：**没有找到能在多地图上稳定超过它的改动**。本文件记录全部实验、数据和原因，
> 失败的实现没有合入（避免在仓库里留下 900 行同水平重复代码）。
>
> 本轮真正的产出是两件事：修正了评测口径，并补上 `tools/bench_ai.py`。

## 1. 先修正评测口径（重要）

内置 AI 几乎确定性：随机数只用于"卡住后破僵局"，同一张地图上 200 局几乎是**同一局重复 200 次**。
所以 `--seed-mode fixed` 下按局数统计会把 8 张图的胜负放大成"3200 局、100% 胜率"：

```bash
# 反例：seed 4 的 200 局全部是同一个结果
target/release/qfr run --matches 200 --teams 2 --ai 0=raider --ai 1=random \
    --out out/x --seed-mode fixed --seed 4
```

正确的泛化测试是 `per-match`（每局新地图种子）+ **双向换槽位**（抵消先手与 AI 种子偏差）：

```bash
./scripts/cargo build --release -p cli
python3 tools/bench_ai.py raider greedy_flag --matches 500 --base-seed 910001
```

### A/A 对照

把同一实现注册成两个名字、互相对打，是验证评测管线无偏的必需步骤：

| 对照 | 局数 | 胜 / 平 / 负 | 结论 |
|---|---|---|---|
| `raider` clone vs `raider` | 800 | 344 / 112 / 344 | 精确 50/50，管线无偏 |

> 如果 A/A 不是 50/50，说明槽位、种子或统计口径有问题，后续数字不可信。

## 2. 实验记录（2 队，`per-match`，双向槽位）

"胜/平/负"是**新 AI 视角**；所有数字都可用 `tools/bench_ai.py` 复现。

| # | 改动 | 局数 | 胜 / 平 / 负 | 结论 |
|---|---|---|---|---|
| 0 | 纯克隆（A/A） | 800 | 344 / 112 / 344 | 50.0%，校准 |
| 1 | 预测设伏（提前 2 格）+ 拦截半径 9→12 | 800 | 337 / 106 / 357 | 回滚（42.1%） |
| 2 | ① + 带权绕路（火力格 +8 步） | 800 | 245 / 102 / 453 | 回滚（30.6%） |
| 3 | ① + 射程内停火 | 800 | 278 / 105 / 417 | 回滚（34.7%） |
| 4 | ① + 护送优先 | 800 | 269 / 92 / 439 | 回滚（33.6%） |
| 5 | ① + 同 tick 集火 | 800 | 323 / 108 / 369 | 回滚（40.4%） |
| 6 | ① + 终局控旗 | 800 | 330 / 103 / 367 | 回滚（41.2%） |
| 7 | **干净克隆** + 终局控旗 | 800 | 347 / 110 / 343 | 中性（≈50%） |
| 8 | 干净克隆 + 拦截"最接近回城"的携带者 | 800 | 331 / 95 / 374 | 回滚（41.4%） |
| 9 | 干净克隆 + 同 tick 集火 | 1000 | 445 / 109 / 446 | 中性（≈50%） |
| 10 | 干净克隆 + 完全不拦截 | 1000 | 260 / 90 / 650 | 灾难（26.0%） |

说明：1–6 号实验是在"已包含 1 号改动"的基线上叠加的，严格说是**组合效果**；
7–10 号是重置成纯克隆后的单变量实验。

### 为什么大部分改动会把强度打下去

看对局数据（60 张随机图，`raider` vs `raider` 镜像）：

| 指标 | 数值 |
|---|---|
| 每队拾旗 | 12.2 次/局 |
| 每队得分 | 8.5 分/局 |
| 携带者阵亡 | 3.0 次/局（约 30% 的拾旗） |
| 平均运输时间（拾旗→得分） | 19.3 tick |

三条解释：

1. **移动速度锁死**：规则 §7.1 规定每单位每 tick 最多 1 次移动，任何"绕路/回头/等一等"
   都直接换算成运输时间。带权绕路（+8 步）让场均分从 8.2 掉到 8.0，对手反而涨到 8.9。
2. **spare 单位的经济价值极高**：不拦截（26%）、拦截半径 12（42%）、拦截最接近回城的
   携带者（41%）都输给半径 9。`raider` 的 9 恰好落在"能打断"与"不脱离中心"的平衡点上。
3. **携带者死亡是结构性的**：攻防双方移速相同，被近身之后基本只能靠墙/拐角断视线。
   路径层面的避让改变不了这一点，真正有效的是"别在敌人堆里拾旗"，而这又会输掉拾旗竞争。

### 集火与控旗为什么是中性

- **集火**：伤害预算在同 tick 内很难兑现——队友的攻击可能因目标移动/死亡落空，
  提前跳过攻击等于白送 1 点伤害。1000 局测下来是精确的 50/50。
- **终局控旗**：领先时把旗压在门外、冻结刷新，理论上很赚；但触发条件苛刻
  （领先 + 场上旗已满 + 剩余 20–40 tick），实战覆盖率太低，800 局里看不到差异。

| 对局 | 局数 | 胜 / 平 / 负 | 场均得分 | 对手场均 |

## 4. 后续可以试的方向

- **炸弹战术**：炸弹 2 点伤害、十字半径 2、友伤，可能用于封锁走廊或收残血；
  但对时机和撤退路线的要求很高，本轮没有实现（需要单独一个 AI 做 A/B，避免污染得分 AI）。
- **队伍级联合搜索**：当前是"每单位独立贪心 + 角色分配"。把 3 个单位的动作放在一起做
  小规模搜索（每 tick 枚举几个候选动作组合）可能找到贪心看不到的配合。
- **3 队专用策略**：3 队时 spare 有 2 个，角色分配与拦截优先级都值得单独调参；
  本轮只在 2 队上做了严格 A/B。
- **更强基线**：自对弈 / MCTS / 学习型策略。现有基线已经是手工启发式的局部最优，
  继续微调参数的收益很低。

## 5. 复现

```bash
./scripts/cargo build --release -p cli

# 2 队 A/B（默认 500 局/顺序，自动双向换槽位）
python3 tools/bench_ai.py raider greedy_flag --base-seed 910001

# 3 队（轮换三个槽位）
python3 tools/bench_ai.py raider greedy_flag defender --matches 250 --base-seed 910003

# 需要行为指标（横跳/停顿/冲突）时，直接跑一批保留回放的产物
./scripts/cargo run -p cli --release -- run --matches 50 --teams 2 \
    --ai 0=raider --ai 1=random --out out/metrics --replay-sample all --jobs 0
python3 tools/analyze_ai.py out/metrics
```
